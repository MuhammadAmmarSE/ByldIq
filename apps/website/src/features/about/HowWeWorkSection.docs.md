# HowWeWorkSection

CLAUDE.md Milestone 13 §§10-11's How We Work With Clients and
Transparency: two closely related themes — a collaboration model, and the
honesty that model depends on — rendered as one component with two
anchors (`#how-we-work`, `#transparency`), the same "one component, two
ids" pattern `CaseStudyOverview` uses for Executive Summary/Business
Challenge.

The collaboration model (Client ↔ Product ↔ Design ↔ Engineering ↔ Byld
IQ) is a static illustration, not an interactive explorer — like
`DesignEngineeringFlow`, there's no per-node detail to inspect.

The Transparency list (risks, technical debt, estimates, trade-offs,
constraints, dependencies, unknowns) is the spec's own list, each with a
short explanation of what "transparent" actually means for that item —
not a generic "we're honest" claim.
